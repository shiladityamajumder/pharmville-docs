Complete Screen Matrix

Generated from the implemented screen registry and authoritative feature inventory. Every row is an actual route. A customer route is shared by the Mobile App and Desktop Website presentations; their navigation and content density change at the selected device width. Staff workspaces are desktop-first responsive websites, not separate mobile apps; the rider workspace is mobile-first.

Platform labels distinguish required product experiences from responsive adaptations. “Not applicable as a standalone app” does not mean the route is unusable on a smaller screen: all routes are included in the six-width responsive browser sweep.

Test IDs refer to the executable suite described in Prototype Test Plan: BR-01 route/render smoke; BR-02 assigned scenario rendering (not an interaction claim); BR-03 six-width layout/overflow; BR-04 named task interaction assertions (only on the rows listing it); BR-05 basic labels, duplicate IDs and route links. Feature coverage status retains the product’s boundary between simulated UI, blocked decisions and backend-only behavior.
