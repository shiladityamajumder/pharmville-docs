Mapping status and gaps

The table links each feature to its owning module. API and database links are module-level indexes; they are not proof of a feature-specific operation or approved table ownership. The historical exact-ID metric identifies 23 features without a mention in their owning API document.

The review below distinguishes supporting owner commands from genuinely absent operations; neither count proves complete contracts. Do not fill those gaps by inventing endpoints or inserting ID mentions without a real mapping. The database module map is schema discovery only.

For ACC-01 and ACC-02, the Customer Accounts LLD, API contracts, and edge cases now define distinct flows, table mapping, and feature-specific tests.

Every feature now has distinct normal/adverse assertions in module LLD/edge pages. Operation schemas and exact write fields still require the review identified in Coverage report.

All development tasks are proposed and not tracked in an issue system. Proposed tests are not executed tests.

Direct API reference gaps measured by owner

A direct reference means an exact feature ID appears in its owning module API file. It does not verify the payload or approval. This is 87/110 after the authentication corrections; 23 lack that reference. Supporting contracts can exist in another module, so these gaps require mapping review rather than automatic endpoint creation.
