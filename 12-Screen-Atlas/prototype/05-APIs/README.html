Shared contract standards

  • API conventions define versioning, public identifiers, casing, request processing and server-generated fields.
  • Authentication and authorization define caller trust, object ownership and candidate headers. D-003 and D-023 remain open.
  • Standard responses define the verified reference envelope and its proposed Pharmville use, including list, async, replay and no-content exceptions.
  • Error catalog gives stable proposed machine codes and retry guidance.
  • Pagination and filtering define scope-safe cursor/offset rules; operation limits and supported fields remain owner decisions unless stated.
  • Idempotency and concurrency define proposed replay and stale-version behavior; D-024 approval remains required.
  • Database-first DTO mapping links operation groups to documented table fields, types, nullability, constraints and relationships while separating persisted, derived and public-only values.
  • OpenAPI 3.1 maps each operation to an owner contract. OpenAPI descriptions/extensions mark proposed contracts and blockers; it does not imply implementation.

Cross-domain invariants

Public catalog reads expose only published safe fields. Catalog availability is advisory; inventory rechecks eligible stock at reservation and picking. Prescription access is private and bound to the correct customer, patient, order revision and evidence. Clinical approval, order acceptance, payment success, stock commitment and delivery completion are distinct business facts.

Browser payment redirects are not authoritative. Signed provider callbacks require D-016 wire evidence, durable deduplication and reconciliation. Staff, warehouse, pharmacist, finance, rider, export and audit access always checks server-side permissions and object scope.

Each module document preserves its feature IDs, candidate data ownership, failure handling and designed test cases. These test scenarios are Designed / NOT RUN unless execution evidence is explicitly cited. The documented authoritative database source folder is absent here, and the adjacent similarly named folder does not match the evidence manifest; only checked-in database documentation is available for this turn.

Review API contract coverage before implementation; remaining incomplete fields and all proposed owner decisions must be approved under D-024.

Standard problem response behavior

Use the existing four-field response envelope and the error catalog. Each endpoint supplies its applicable error triggers and recovery; protected failures redact patient, credential, provider and hidden-resource information. HTTP 204 has no body. Shared envelope reuse does not replace an operation DTO.
