- **Authentication decisions:** D-003 (Security and Product owner) must approve credential paths, effective OTP/MFA/refresh/revocation policies and challenge limits.

- **Operation DTO and database mapping:** D-024 (Tech lead, module owners and QA lead) must approve per-operation fields, permissions, database writes, transaction boundaries, transitions and tests. The seven critical request schemas are carried into OpenAPI as proposed refinements from `Critical-Operation-Contracts.md`; the rest need operation-level schemas.
- **Provider contract:** D-016 (Product owner and Security/provider owner) blocks Cashfree webhook header names, canonicalization, event payload and acknowledgment details. No provider-specific wire fields or header names are invented.
- **Database evidence:** The documented `healthcare_db/` source path is absent from the workspace. The adjacent `heathcare_db/` directory is a different, non-matching source: direct SHA-256 comparison against the evidence manifest found only 17 of 77 listed files matching, 45 missing and 15 mismatched. Therefore this API package relies on checked-in `04-Database/` documentation only; source-level migration/model verification and runtime verification remain outstanding. Do not use the adjacent directory as the authoritative Pharmville database source.
- **Tests:** Every operation test listed in module documents is designed coverage unless separately marked with execution evidence. Documentation and OpenAPI validation do not execute API behavior.
- **Schema gaps:** Most operation request/response DTOs, list filters, success status details, response headers, query pagination limits, permission strings, field-to-column mappings, audit/outbox effects, and transaction-failure cases remain unresolved and block implementation readiness.
