## API-076 — POST `/v1/webhooks/cashfree`

**Status:** Proposed provider callback for `FIN-01` and payment completion in `CHK-03`. Finance_Payments owns verification and persisted payment facts; Cart_Checkout consumes the verified result. This endpoint does not require a customer or staff bearer session.

### Provider authentication and input

Accept the provider's raw HTTP payload and signature/timestamp headers. Verify them against the approved merchant account, API version and signing contract before processing any payment state. Reject invalid signatures without changing payment/order rows. Do not invent provider header names or payload schemas: exact wire examples and signing algorithm remain D-016 vendor-contract evidence. Reject a callback that cannot be matched to the expected merchant, currency, amount and payment/order reference. Do not trust caller-supplied user IDs or browser redirect status.

### Commit, acknowledgement and recovery

Persist a durable deduplication/inbox record keyed by provider account and event identifier, then update the matched payment state under concurrency control. A duplicate event produces no second charge, order confirmation or notification. Reordered callbacks cannot regress a terminal state; contradictory provider facts go to reconciliation rather than silently rewriting history. Acknowledge with `2xx` only after durable acceptance commits. On transaction failure return a retryable failure and do not acknowledge success. If the acknowledgement is lost, safe provider replay must return success for the already committed event.

After commit, publish the order/payment outcome through the outbox. Delivery failure of that event is retried without replaying the money effect. Late success after checkout expiry/cancellation must enter the approved Finance recovery/refund policy (D-004); never recreate a cancelled order or release a second reservation automatically. The provider retry window and exact response requirements must be confirmed in D-016.

### Data and verification

Use `payment.payment_webhooks` for provider facts and the matched `payment.payment_intents`/`payment.payment_transactions` records, with `platform.inbox_messages` and `platform.outbox_events` where the approved adapter design uses them. These are local schema references, not an implemented adapter. Required tests cover signature tampering, wrong merchant/amount/currency, duplicate and reordered callbacks, concurrent consumers, transaction rollback, lost acknowledgement, late payment and outbox replay. No live provider test is claimed.
